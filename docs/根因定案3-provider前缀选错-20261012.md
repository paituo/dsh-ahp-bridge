## 三、根因

**我们把 provider id 定成了 `agenthost-dsh`（无连字符），而 VS Code 的权威 scheme 前缀是 `agent-host-`（带连字符）。**

⇒ renderer 把 session 记为 `agent-host-<provider>`，而注册表键是 `agenthost-dsh`
⇒ `sessionsProvidersService.getProvider(session.providerId)` **查不到**
⇒ `_getProvider` 返回 undefined ⇒ `_initAgent` 提前 return ⇒ **picker 兜底**
⇒ 同源 ⇒ `getActiveDescriptor().id` 与命令名 `openNewSessionSidebar.${id}` 也对不上 ⇒ **迁移报错**

## 四、`bI`/`vr` 的语义澄清（前一版误读）

- `vr(s)=bI(s.id)` 里的 `s` **是 agent-host session（或其 sessionConfig）**，`s.id` 是 **session id**；
  典型 `id` 形态 **`local-agent-host`** 或 **`agenthost-<...>`**（对应 §2.4 里 `local-agent-host:agent-host-copilotcli:...` 的**前半段**）。
- **它检查的不是 provider.id**。前一版注释把 `vr(provider)` 与 `vr(session)` 混为一谈 ⇒ 得出"id 必须 `agenthost-`"的错误约束。

## 五、修复方案（待实测确认，二选一）

| 方案 | 动作 | 依据 | 风险 |
|---|---|---|---|
| **A（推荐）** | 注入里 `const ID = "agent-host-dsh"`，桥 `--provider-id agent-host-dsh` 同步 | §2.3/§2.4 权威前缀 | 若 VS Code 会自动补前缀 ⇒ 变成 `agent-host-agent-host-dsh`（需实测） |
| **B** | 注入里 `const ID = "dsh"`（纯名，让 VS Code 补前缀） | 对照 `copilotcli` → `agent-host-copilotcli` | 与历史"`dsh` 不工作"的记录冲突，需重测（当时结论建立在误读的 `bI` 上） |

**实测判据**：改后重启，Agent 窗口 `document.documentElement.outerHTML` 里应出现
`agent-host-dsh:/<uuid>`，且 picker 展开出现 5 个 preset（标准/PTC/极简/创作者/梁神）。
